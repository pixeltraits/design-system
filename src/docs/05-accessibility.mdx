# Accessibilité

Le design system vise la conformité **WCAG 2.1 niveau AA**. Une partie des
règles est portée par les composants eux-mêmes — l'autre dépend du contexte
d'intégration et reste à la charge de l'application consommatrice.

Chaque story est validée par **`@storybook/addon-a11y`**. Le rapport
`axe-core` apparaît dans l'onglet **A11y** du panneau bas de Storybook,
et la condition pour qu'un composant soit publié est zéro violation.

## Responsabilités à l'intégration

Le contexte d'usage échappe au composant. L'application consommatrice
fournit les libellés contextuels, les landmarks de page, les attributs
d'état applicatif.

### Noms accessibles

Un composant qui n'a pas de libellé textuel intrinsèque doit recevoir un
`aria-label`.

<div className="a11y-grid">
  <div className="a11y-card a11y-card--bad">
    <div className="a11y-card__title">À éviter</div>
```html
<button dsButton="primary">
  <ds-icon icon="xmark" />
</button>
```
*Lecteur d'écran : « bouton ».*
  </div>
  <div className="a11y-card a11y-card--good">
    <div className="a11y-card__title">À faire</div>
```html
<button
  dsButton="primary"
  aria-label="Fermer la modale">
  <ds-icon icon="xmark" />
</button>
```
*Lecteur d'écran : « bouton, fermer la modale ».*
  </div>
</div>

### Icônes décoratives et informatives

Une icône accompagnée d'un texte est décorative — l'élément qui la porte
prend `aria-hidden="true"` pour éviter la double lecture.

<div className="a11y-grid">
  <div className="a11y-card a11y-card--bad">
    <div className="a11y-card__title">À éviter</div>
```html
<button dsButton="primary">
  <ds-icon icon="trash" />
  Supprimer
</button>
```
*Lecteur d'écran : « trash, Supprimer, bouton ».*
  </div>
  <div className="a11y-card a11y-card--good">
    <div className="a11y-card__title">À faire</div>
```html
<button dsButton="primary">
  <span aria-hidden="true">
    <ds-icon icon="trash" />
  </span>
  Supprimer
</button>
```
*Lecteur d'écran : « Supprimer, bouton ».*
  </div>
</div>

### Landmarks de page

Le DS fournit des briques. La page consommatrice pose les landmarks
(`<header>`, `<nav>`, `<main>`, `<footer>`) qui structurent la lecture
au lecteur d'écran.

<div className="a11y-grid">
  <div className="a11y-card a11y-card--bad">
    <div className="a11y-card__title">À éviter</div>
```html
<div class="page">
  <div class="nav">...</div>
  <div class="content">...</div>
  <div class="footer">...</div>
</div>
```
*Aucun landmark — pas de saut possible pour un lecteur d'écran.*
  </div>
  <div className="a11y-card a11y-card--good">
    <div className="a11y-card__title">À faire</div>
```html
<header><nav aria-label="Principale">…</nav></header>
<main id="main-content">
  …
</main>
<footer>…</footer>
```
  </div>
</div>

### États contextuels (aria-current, aria-expanded)

Le composant connaît son état interne. L'état applicatif (page active,
menu ouvert) vient de la page qui l'utilise et doit être propagé en
attribut ARIA.

<div className="a11y-grid">
  <div className="a11y-card a11y-card--bad">
    <div className="a11y-card__title">À éviter</div>
```html
<a routerLink="/blog"
   routerLinkActive="is-active">
  Blog
</a>
```
*La classe visuelle signale l'état mais le DOM ARIA reste muet.*
  </div>
  <div className="a11y-card a11y-card--good">
    <div className="a11y-card__title">À faire</div>
```html
<a routerLink="/blog"
   routerLinkActive="is-active"
   #rla="routerLinkActive"
   [attr.aria-current]="rla.isActive ? 'page' : null">
  Blog
</a>
```
  </div>
</div>

### Liens externes

`target="_blank"` impose `rel="noopener noreferrer"` et un signal explicite
que le lien ouvre un nouvel onglet.

```html
<a href="https://github.com/codelyr"
   target="_blank"
   rel="noopener noreferrer"
   aria-label="GitHub Codelyr (ouvre un nouvel onglet)">
  GitHub
</a>
```

`DsActionCard` pose automatiquement ces attributs quand l'input `external`
vaut `true`.

### Modales et overlays

`DsDialog` (basé sur `MatDialog`) applique `role="dialog"` et
`aria-modal="true"`, et utilise `cdkTrapFocus` du CDK Material. Le
consommateur prend en charge le reste.

- Le titre accessible passe par `aria-labelledby` pointant vers le titre
  interne, ou un `aria-label` quand aucun titre n'est visible.
- La fermeture sur `Escape` est active par défaut (`disableClose: false`).
- Le focus est rendu au déclencheur à la fermeture (géré par le CDK).

## Patterns récurrents

### Bouton icône-seule

```html
<button type="button"
        dsButton="secondary"
        aria-label="Copier le code">
  <ds-icon icon="copy" />
</button>
```

### Navigation principale

```html
<nav aria-label="Navigation principale">
  <ul>
    <li>
      <a routerLink="/"
         routerLinkActive="is-active"
         [routerLinkActiveOptions]="{ exact: true }"
         #rla="routerLinkActive"
         [attr.aria-current]="rla.isActive ? 'page' : null">
        Accueil
      </a>
    </li>
    <li>…</li>
  </ul>
</nav>
```

### Toggle d'état (mode jour / nuit)

`DsThemeToggle` porte sa sémantique radiogroup en interne. L'input
`ariaLabel` suffit à le rendre intelligible.

```html
<ds-theme-toggle
  ariaLabel="Mode d'affichage du site"
  [(value)]="theme" />
```

### Modale custom hors DsDialog

```html
<div role="dialog"
     aria-modal="true"
     aria-label="Contact"
     cdkTrapFocus
     [cdkTrapFocusAutoCapture]="true">
  <button type="button"
          aria-label="Fermer"
          (click)="close()">
    <span aria-hidden="true">&times;</span>
  </button>
  <ng-content />
</div>
```

Mémoriser le déclencheur avant l'ouverture et lui rendre le focus à la
fermeture (`queueMicrotask(() => trigger.focus())`).

### Live region pour feedback asynchrone

```html
<div role="status" aria-live="polite">
  @if (isLoading()) {
    Chargement…
  } @else if (error()) {
    Erreur — impossible de charger les liens
  }
</div>
```

`aria-live="assertive"` reste réservé aux erreurs critiques — les autres
cas conservent `polite` pour ne pas interrompre la lecture en cours.

## Vérification

### Pendant le développement

L'onglet **A11y** de Storybook affiche un rapport `axe-core` en temps
réel sur le composant courant. La toolbar **Thème** permet de vérifier
les contrastes dans les deux palettes.

### En intégration

- **Axe DevTools** (extension navigateur) sur chaque page complète.
- **Lighthouse**, catégorie *Accessibility* ≥ 95.
- Navigation au clavier seul — `Tab`, `Shift+Tab`, `Enter`, `Espace`,
  `Escape`. Pas de zone piégée, pas d'élément inatteignable.
- Lecteur d'écran (NVDA / VoiceOver) sur les flux critiques : formulaires,
  modales, navigation principale.

### Cibles tactiles

Les éléments interactifs visent **44 × 44 px** minimum (WCAG 2.5.5 AAA,
ramené à 24 × 24 px en AA via 2.5.8 avec clearance suffisante). Le DS
respecte cette règle pour ses composants principaux ; le toggle passe à
26 × 26 px en mobile, à corriger lors d'une passe responsive ultérieure.
