`@pixeltraits/design-system` est un design system Angular 21 standalone,
basé sur Angular Material M3. Le package se consomme via npm comme une
dépendance classique.

## Pré-requis

Toutes les dépendances ci-dessous sont des `peerDependencies`. Elles sont
fournies par l'application consommatrice.

## Installation

```bash
npm install @pixeltraits/design-system \
  @angular/material @angular/cdk \
  @fortawesome/angular-fontawesome \
  @fortawesome/fontawesome-svg-core \
  @fortawesome/free-solid-svg-icons \
  @fortawesome/free-regular-svg-icons \
  @fortawesome/free-brands-svg-icons
```

## Configuration SCSS

Le thème du DS se charge dans `src/styles.scss`, point d'entrée global de
l'application Angular. Une seule inclusion suffit — le mixin pose les
tokens Material (`--mat-sys-*`) et les tokens du DS (`--ds-*`) en une
fois.

```scss
// src/styles.scss
@use '@pixeltraits/design-system/styles' as ds;

html {
  @include ds.theme();
}
```

Le mixin `ds.theme()` applique la palette jour par défaut, déclenche la
palette nuit sur tout élément porteur de `[data-theme='night']` à
n'importe quel niveau du DOM, et déclare les tokens partagés (typographie,
échelles de taille et de poids).

La cascade complète est décrite dans **Docs › Theme & Day-Night**.

## Utilisation d'un composant

Les composants du DS sont standalone et s'importent directement dans le
`imports[]` du composant Angular qui les utilise.

```ts
import { Component } from '@angular/core';
import { DsButton, DsIcon } from '@pixeltraits/design-system';

@Component({
  selector: 'app-root',
  imports: [DsButton, DsIcon],
  template: \`
    <button dsButton="primary">
      <ds-icon icon="check" /> Valider
    </button>
  \`,
})
export class App {}
```

## Architecture interne

Le code source du DS suit une architecture hexagonale (`domain` /
`application` / `infrastructure` / `presentation`). Les composants vivent
dans `presentation/`. Les ports et adapters internes ne sont pas exposés
publiquement — la surface publique se limite à `public-api.ts`.

## Versioning

Le package suit du `semver` (`major.minor.patch`). Les changements
breaking sur les tokens, les inputs publics ou les sélecteurs déclenchent
un bump majeur. Les nouveaux composants, tokens et stories arrivent en
minor.

## Validation

Chaque composant possède sa story (`<feature>.stories.ts`) validée par
`@storybook/addon-a11y`. Le rapport `axe-core` apparaît dans l'onglet
**A11y** du panneau bas de Storybook et la condition pour qu'un composant
soit publié est zéro violation.

Storybook local : `npm run storybook`.
